# 4. 도메인 규칙 — 시트를 AI가 이해하게

## 4.1 왜 규칙 문서가 필요한가

```text
채팅만          → 열 배치·합산이 매번 달라짐
도메인 MD + 채팅 → 같은 패턴으로 재현 가능
```

## 4.2 기본 열 패턴

| 열 | 헤더 예 (한) | 헤더 예 (영) | 합산 |
|----|--------------|--------------|------|
| A | 그룹 | group | 키 |
| B | 할 일 | item | — |
| C | 참고·벤치마크 | reference | **아니오** |
| D | 잔여·건수 | residual | **예 (SUMIF)** |
| E | 담당 역할 | role | 직함만 |
| F | 상태 | status | — |
| G | 사람 확인 | human_check | — |

### 그룹 값

| 값 (한) | 값 (영) | 합산 |
|---------|---------|------|
| 필수 | must | D열에 포함 |
| 선택 | optional | 별도 합 가능 |
| 참고 | note | **합산 제외** (수치는 C열) |

### 이중 합산 금지

참고용 총량(C)과 앞으로 할 건수(D)를 **더하지 마세요.**  
참고 행 비고에 `합산 금지` 를 적습니다.

## 4.3 품질 체크리스트

- [ ] 헤더 행 있음  
- [ ] 그룹 열 비어 있지 않음  
- [ ] C/D 역할이 섞이지 않음  
- [ ] 역할은 직함 수준 (실명 없음)  
- [ ] 불확실 → `확인 필요`  
- [ ] 실존 개인·기관 식별정보 없음
